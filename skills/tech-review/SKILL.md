# 技术评审规范

## 评审维度（6 个）

### 1. 数据模型影响
- 是否需要新增数据表？
- 现有表是否需要新增字段？
- 字段类型和约束是否合理？
- 是否涉及数据迁移？
- 数据量预估和索引设计

### 2. 接口设计
- 需要新增哪些 RESTful API？
- 现有接口是否需要修改？
- 接口的请求/响应格式是否合理？
- 向后兼容性如何保证？
- 接口幂等性设计

### 3. 权限影响
- 是否需要新增菜单权限？
- 是否需要新增按钮权限？
- 是否需要新增接口权限？
- 新增角色的权限范围？
- 与现有 RBAC 三层权限体系的兼容性

### 4. 跨端影响
- 新功能是否影响其他端的数据展示？
- 数据同步机制是否需要调整？
- 状态流转在各端是否一致？
- 消息通知是否覆盖所有相关端？

### 5. 性能风险
- 大数据量场景（列表查询、报表统计）
- 并发场景（竞价出价、抢购）
- 第三方 API 调用延迟
- 文件上传/下载性能

### 6. 安全考量
- 数据隔离是否充分（应用间/机构间）？
- 越权防护是否到位？
- 敏感数据加密存储？
- 输入校验是否完整？

## 风险等级定义

| 等级 | 含义 | 处理建议 | 示例 |
|:----:|------|---------|------|
| **P0-阻断** | 技术不可行或重大架构变更 | 需重新评估需求 | 违反应用隔离原则 |
| **P1-高风险** | 实现复杂度高，影响范围广 | 需架构评审 | 跨 3 个端的状态联动 |
| **P2-中风险** | 有一定复杂度，影响范围可控 | 需 Code Review | 新增数据表关联查询 |
| **P3-低风险** | 常规实现，影响范围小 | 正常开发 | 新增 CRUD 页面 |

## 工作量估算方法

| 功能类型 | 基准人天 | 说明 |
|---------|:-------:|------|
| 简单 CRUD 页面 | 1-2 | 列表+新增+编辑+删除 |
| 复杂表单页面 | 2-3 | 多字段、联动校验、文件上传 |
| 状态流转逻辑 | 2-4 | 状态机设计+异常处理 |
| 支付/资金相关 | 3-5 | 对账+异常处理+安全校验 |
| 跨端联动 | 2-3/端 | 每个端的适配工作量 |
| 第三方对接 | 3-5 | 接口联调+异常处理 |

| 预估工作量 | X 人天 |
| 高风险项 | X 个 |
| 中风险项 | X 个 |
| 低风险项 | X 个 |

## 逐项评审

### [功能模块名称]

| 维度 | 可行性 | 风险等级 | 说明 |

| 接口设计 | ✅ | P3 | 标准 CRUD |

| 跨端影响 | ✅ | P3 | 仅影响本端 |

| 安全考量 | ✅ | P3 | 标准鉴权 |

## 风险清单

## 技术方案建议

## 评审检查清单

- [ ] 每个功能模块是否都覆盖了 6 个维度
- [ ] 风险等级是否合理
- [ ] 工作量估算是否有依据
- [ ] 是否给出了可操作的改进建议
- [ ] 是否识别了数据隔离风险
- [ ] 是否考虑了向后兼容性
