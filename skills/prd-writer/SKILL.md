# PRD 编写规范

## PRD 标准结构（13 章节，严格按顺序）

| 章节 | 名称 | 核心内容 |
|:---:|------|---------|
| 1 | 需求背景 | 业务现状、痛点、为什么需要这个功能 |
| 2 | 需求目标 | 业务目标和衡量指标（表格：目标类型/目标描述/衡量指标） |
| 3 | 原型链接 | 各端原型链接表格（端/页面名称/原型链接） |
| 4 | 已有功能说明 | 4.1 现有功能概述 / 4.2 与本次需求关系 |
| 5 | 模块影响分析 | 5.1 影响概览 / 5.2 核心影响分析 / 5.3 风险评估 |
| 6 | 功能范围 | 表格：端/功能模块/页面/功能描述/优先级 |
| 7 | 名词解释 | 表格：名词/定义/示例（必须与知识库术语一致） |
| 8 | 用户故事 | 8.1 用户角色定义 / 8.2 故事列表 |
| 9 | 业务流程图 | 9.1 主流程 / 9.2 分支流程 / 9.3 异常流程 |
| 10 | 业务逻辑说明 | 10.1 核心规则 / 10.2 数据流转 / 10.3 状态流转（多端子状态表） |
| **11** | **功能需求** | **核心章节，按端→功能模块组织（详见下方）** |
| 12 | 非功能需求 | 12.1 性能 / 12.2 安全 / 12.3 兼容性 / 12.4 可用性 / 12.5 短信与站内信 |
| 13 | 附录 | 相关文档、变更记录 |

## 标题编号规则（🔴 必须执行）

所有层级标题必须带数字编号，格式为层级式阿拉伯数字：

| 层级 | 格式 | 示例 |
|------|------|------|
| H2（章） | `## N. 名称` | `## 1. 需求背景` |
| H3（节） | `### N.M 名称` | `### 5.2 核心影响分析` |
| H4（模块） | `#### N.M.K 名称` | `#### 11.1.2 查询申请 — 律师流程` |
| H5（模块内段） | `##### N.M.K.L 名称` | `##### 11.1.2.1 需求描述` |
| H6（页面/步骤） | `###### N.M.K.L.P 名称` | `###### 11.1.2.3.1 步骤1` |

**新增标题时必须同步编号**，编号随所属层级自动递增。

## 第十一章"功能需求"格式（核心，最容易出错）

每个功能模块（`#### 11.x.x`）必须严格按以下结构：

```markdown
#### 11.x.x [功能模块名称]

##### 11.x.x.1 需求描述
（多段文字，描述核心功能、业务目标、使用场景、涉及角色、与上下游的关系。
不允许只写一句话！至少 3 段。）

##### 11.x.x.2 核心交互流程
（按 Case 组织，每个操作场景单独编号）

**Case 1：[操作名称，如：创建工单]**
1. 用户进入[页面]
2. 系统展示[内容]
3. 用户[操作]
4. 系统[响应]

**Case 2：[操作名称，如：编辑工单]**
1. ...

##### 11.x.x.3 页面说明

**页面层级结构**：
```
[父页面]
  ├── [子页面1：列表页]
  │     └── [详情页]
  └── [子页面2：新增弹窗]
```

**各页面说明**：

###### 11.x.x.3.1 [页面1名称]

###### 字段说明
| 字段 | 必填 | 类型 | 来源 | 约束 | 说明 |
|------|:---:|------|------|------|------|
| 字段A | 是 | 文本 | 输入 | — | — |
| 字段B | — | 金额 | 系统 | — | — |

> **强制规则：每个字段独占一行，禁止将多个字段合并为一行（如“字段A/字段B”或“字段A(子字段1/子字段2)”）。列表/表格字段须拆分为每列一行，用“表名-列名”命名。**

###### 校验规则
| 字段 | 规则 | 错误提示 |
|------|------|--------|

###### 异常处理
| 异常 | 处理 | 提示 |
|------|------|------|

###### 原型
- **预览链接**：[待 UED 填充]

###### 11.x.x.3.2 [页面2名称]
（同上结构）
```

## 绝对禁止清单

- 不写 `##### 11.x.x.1 需求描述` 标题
- 需求描述只写一句话
- 不写页面层级结构
- 页面下遗漏 `**字段说明**` / `**校验规则**` / `**异常处理**` / `**原型**`
- 出现 "交互说明" / "关键交互点" 等旧模板废弃段落
- 自造业务术语（必须使用知识库中定义的标准术语）
- **字段说明表中将多个字段合并为一行（每个字段必须独占一行）**

## 影响分析前置要求

在写 PRD 之前，必须完成以下分析：

### 各端联动分析（最前置）

根据所属应用确定联动范围：
- **这里拍**：运营端、商家端、服务商端、用户端（4 端）
- **这里查**：运营端、渠道端、用户端（3 端）

分析内容：
- 数据流在各端之间如何流转
- 订单流（如适用）在各端之间如何流转
- 资金流（如适用）在各端之间如何流转
- 修改一个端对其他端的影响

### 12 个影响维度

| # | 维度 | 分析内容 |
|---|------|---------|
| 1 | 功能模块 | 直接关联、间接关联、上下游模块 |
| 2 | 数据 | 数据表、字段、数据量、数据迁移 |
| 3 | 接口 | 新增、修改、删除、兼容性 |
| 4 | 第三方依赖 | API、SDK、外部服务 |
| 5 | 性能 | 响应时间、并发量、资源消耗 |
| 6 | 安全 | 权限、加密、输入校验 |
| 7 | 兼容性 | 浏览器、移动端、旧版本 |
| 8 | 运维 | 部署、发布、回滚、监控 |
| 9 | 测试 | 测试范围、回归测试 |
| 10 | 运营 | 用户通知、培训、客服 |
| 11 | 用户体验 | 使用流程变化、学习成本 |
| 12 | 业务 | 业务流程、收入、成本 |

## 变更记录规则（🔴 必须执行）

**每次 PRD 变更（新增/删除/修改字段、功能、流程）都必须记录到 PRD 第十三章 13.2 变更记录表中。**

### 主记录位置：13.2 变更记录（Markdown表格）

格式：

```markdown
| 版本 | 日期 | 修改人 | 修改内容 |
|-----|------|-------|---------|
| v2.0 | 2026-06-06 | PD Agent | [Q25] 变更描述 |
```

### 辅助记录：文件头部 HTML 注释（摘要）

文件头部保留变更摘要（编号列表），用于快速扫描：

```html
<!-- v[n]变更日志:
[Q25] 变更描述
-->
```

### 注意事项
- 变更编号连续递增（不重置），13.2 和 HTML 注释保持同步
- 描述需具体到字段级别（如"新增单位住所字段"而非"OCR字段调整"）
- 同一次修改涉及多处变更时，每个变更点单独编号
- **13.2 为正式变更记录，必须完整；HTML 注释为摘要，可精简**
- **变更记录按倒序排列**：最新的变更在列表最前面，最早的（v1.0初稿）在最后面

## HTML 在线浏览页生成（🔴 必须执行）

**每次 PRD 创建或修改后，必须生成 HTML 在线浏览页并上传 OSS。**

### 生成方式

用本技能自带的渲染脚本（零第三方依赖，输出**单文件 HTML**），直接复制执行：

```bash
# macOS 本机没有系统 node/npm，统一使用 harness 自带 node
/Users/a131/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/node/bin/node \
  /Users/a131/Documents/deepseek-harness/default-workspace/PMSkill/skills/prd-writer/scripts/render_prd_html.mjs \
  <PRD 的 .md 路径> -o <输出 .html 路径> \
  --title "PRD-xxx" --version "v1.5"
```

- 参数：`--title` 缺省取正文第一个 H1（再缺省取输入文件名）；`--version` 渲染到顶部粘性标题栏的版本徽章，**缺省不显示徽章**（版本号取第十三章 13.2 变更记录表的最新版本）。
- 脚本把 **marked 源码 + CSS + 页面 JS 全部内联**进单个 HTML，产物**零 CDN、零外部请求**（`grep -E '(src|href)="https?:'` 应为 0），可直接上传 OSS 打开。
- 渲染库固定为 **marked v18.1.0（MIT）**，已本地 vendor 在 `vendor/marked.umd.js`（版本、来源 URL、校验和与更新方式见 `vendor/README.md`）；**不要**改回 CDN 引用，也不要 npm/pnpm 安装依赖，更不要引 mermaid。
- **本机路径替换方式**：换机器或换仓库位置时，只替换上面两条绝对路径即可——
  - node：`NODE=$(command -v node || echo ~/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/node/bin/node)`
  - 脚本：`<本仓库根目录>/skills/prd-writer/scripts/render_prd_html.mjs`（本机为 `/Users/a131/Documents/deepseek-harness/default-workspace/PMSkill/...`）
- 输入/输出相对路径按**当前工作目录**解析，不确定时直接给绝对路径；脚本会在渲染后自检"外部资源引用 = 0 / 内联脚本可安全解析"，不通过则非零退出。

### 图片与原始 HTML 的边界（实测确认）

- **允许**：内联 SVG（团队约定流程图手绘 SVG 内联，会原样保留在正文）、`data:` URI 图片（内联，不违反自包含）。
- **会被拦下（非零退出）**：`<img src="https://…">` 外链、`<img src="images/a.png">` 这类相对路径（传到 OSS 会 404）、`<style>@import …</style>`、CSS `url(//…)`。这些都是"未内联的外部引用"，请改为内联 SVG 或 `data:` URI。
- ⚠️ **原始 HTML 会穿透**：marked 默认放行 markdown 里的原始 HTML，所以正文里写的 `<script>…</script>` **会被原样保留成可执行脚本**。浏览页是挂在**匿名可读**的 OSS 上的，因此**不要在 PRD 里粘贴 `<script>`**（从网页复制的片段尤其注意）；渲染器的自检不会拦截正文里的 `<script>`。

### HTML 模板要求

- 左侧固定目录导航（H1-H6 全6层标题层级缩进，滚动高亮）
- 侧边栏整体可收起/展开（✕按钮收起，☰按钮展开，带CSS平滑动画，收起后正文区域全宽展示）
- 每个 H2 章节支持展开/收起（▼按钮点击切换，默认展开，滚动时自动展开当前章节）
- 标题样式覆盖H1-H6（H1=2em/H2=1.5em/H3=1.2em/H4=1.05em/H5=0.95em/H6=0.9em）
- 侧边栏缩进层级：H2=12px/H3=24px/H4=36px/H5=48px/H6=60px
- TOC 生成选择器覆盖：`h1, h2, h3, h4, h5, h6`
- 顶部粘性标题栏（含版本号徽章）
- Markdown 内容区（表格/代码块/引用块样式优化）
- 回到顶部按钮
- 移动端自适应（隐藏侧边栏）
- OSS 上传路径：`prd/PRD-[名称].html`，Content-Type: `text/html; charset=utf-8`

### OSS 上传

上传动作统一交给 `oss-upload` 技能（本仓库唯一的上传实现：零第三方依赖的签名 + `--verify` 上传后校验），**不要再用旧的 `ali-oss` 代码片段**。

- bucket key：`ai-auction-analysis/v1-售前分析/PRD-[名称].html`（前缀按项目，见 `oss-upload` 技能的前缀表）
- Content-Type：`text/html; charset=utf-8`（否则浏览器会下载而不是渲染）
- 凭据由 `oss-upload` **运行时**读取（环境变量或既有脚本），**不要把密钥写进配置文件或本仓库**
- **无凭据时降级**（🔴）：先排查 `credentialsFrom` 指向的既有脚本是否有效；确实取不到时才改用本地 HTTP 服务预览，并在交付说明中注明「**未上传 OSS，交付未完成**」
- 上传通过 `--verify` 后，把**公网链接**（`https://demo.ddys-inc.com/...`）回填到 PRD 的「原型链接」章节；**本地预览地址不得占用主链接位**
