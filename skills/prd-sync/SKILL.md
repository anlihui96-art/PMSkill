# PRD 关联文件全量同步

## 何时触发

**任何需求修改**完成后自动执行，包括：
- 新增/删除/修改字段
- 新增/删除/修改功能或页面
- 重命名（模块名、字段名、状态名）
- 流程变更、状态变更、规则变更

## 执行流程

```
Task Progress:
- [ ] Step 1: 执行用户明确要求的修改（主文件）
- [ ] Step 2: 识别所有关联文件
- [ ] Step 3: Grep 扫描关键词，定位所有受影响位置
- [ ] Step 4: 逐一同步修改所有关联文件
- [ ] Step 5: 同步导航页（总导航页 + 迭代导航页，强制）
- [ ] Step 6: Grep 验证无遗漏
```

---

## Step 1：执行主修改

先完成用户明确要求的改动，这是后续同步的基础。

**同步记录变更日志**：在 PRD 第十三章 13.2 变更记录表中追加变更行，同时更新文件头部 HTML 注释摘要（编号连续递增，描述具体到字段级别）。

---

## Step 2：识别关联文件

### 2.1 扫描项目结构

用 Glob 找出项目中所有 `.md` 和 `.html` 文件：

```
Glob("**/*.md")   → 找出所有文档
Glob("**/*.html") → 找出所有原型页面
```

### 2.2 分类文件

将文件分为两类：

| 类型 | 说明 | 处理方式 |
|------|------|---------|
| **活跃文档** | 当前版本的 PRD、功能列表、页面结构、上下文文档、原型页面 | **必须同步** |
| **历史快照** | 旧版 PRD（如 v1）、评审文档（review）、集成报告、变更日志 | **不修改** |

**判断标准**：
- 文件名含版本号且不是最新版本 → 历史快照（如 `PRD-v1.md`，当 v2 已存在时）
- 文件在 `reviews/`、`archive/`、`history/` 目录下 → 历史快照
- 其余 → 活跃文档

---

## Step 3：Grep 扫描关键词

### 3.1 提取变更关键词

从用户请求和主修改中提取所有相关关键词，例如：

| 变更类型 | 提取的关键词 |
|---------|------------|
| 重命名模块 | 旧名称、新名称 |
| 删除字段 | 字段名（中文+英文+驼峰） |
| 新增功能 | 功能名、相关页面名 |
| 流程变更 | 涉及的步骤名、状态名 |

### 3.2 全局扫描

对每个关键词执行 Grep，搜索所有活跃文档：

```
Grep(keyword, glob="*.md", path="project_root")
Grep(keyword, glob="*.html", path="project_root")
```

### 3.3 汇总影响清单

将所有命中位置汇总为表格：

| 文件 | 行号 | 匹配内容 | 需要修改 |
|------|:---:|---------|:-------:|
| context.md | 23 | 旧模块名 | ✅ |
| feature-list.md | 42 | 旧字段名 | ✅ |
| reviews/qa-review.md | 214 | 旧规则 | ❌ 历史快照 |

---

## Step 4：批量同步

### 4.1 修改优先级

按文件重要性排序修改：
1. PRD 主文档
2. 功能列表（feature-list）
3. 页面结构（page-structure）
4. 上下文文档（context.md）
5. PRD 附录（prd-append）
6. HTML 原型页面
7. 导航页

### 4.2 同步要点

**每个关联文件需检查的内容**：

| 文件类型 | 检查项 |
|---------|-------|
| PRD 主文档 | 字段表、校验规则、流程描述、页面结构树、名词解释、用户故事 |
| 功能列表 | 功能描述、用户故事、联动规则、边界情况 |
| 页面结构 | 导航结构、页面层级、跳转关系 |
| 上下文文档 | 目标表、影响范围、用户故事、Phase 结论 |
| HTML 原型 | 侧边栏、表头、弹窗字段、JS 逻辑、nth-child 索引 |

### 4.3 使用 TodoWrite 追踪

每修改一个文件，更新任务状态：

```
TodoWrite(merge=true, todos=[{id: "sync-文件", status: "COMPLETE", content: "同步 文件名（N处）"}])
```

---

## Step 5：同步导航页（强制，每次修改后必做）

任何原型页面、PRD 版本、页面文案的变更，完成后**必须**同步两级导航页，缺一不可：

| 导航页 | 位置 | 内容 |
|--------|------|------|
| **总导航页** | 应用根目录 `index.html`（如 `output/zhelicha/index.html`） | 全局入口，含所有版本 Tab |
| **迭代导航页** | 当前迭代目录（如 `v6-OpenAPI/prototype/index.html`） | 本迭代页面清单 |

### 导航页同步检查项（逐项核对）

1. **页面总数**：头部统计数字（如「3个版本 · 49个页面」、「10个页面 · PRD v1.5」）与实际卡片数一致
2. **PRD 版本徽章**：版本升级后同步更新（如「📘 PRD v1.4 在线浏览」→ v1.5）
3. **卡片文案**：受影响卡片的描述文案更新为最新交互/规则
4. **卡片增删与编号**：新增页面加卡片、删除页面移除卡片，后续卡片**重新连续编号**（不留空号）
5. **分组计数**：如「用户端 · 收银台升级（3个页面）」的括号内数量同步
6. **最近更新时间**：每次更新后，必须将总导航页头部右上角的「最近更新：yyyy-MM-dd HH:mm:ss」刷新为当前系统时间，**具体到秒**（先用命令取真实时间，禁止沿用旧时间或估算）：
   - macOS / Linux：`date '+%Y-%m-%d %H:%M:%S'`
   - Windows PowerShell：`Get-Date -Format "yyyy-MM-dd HH:mm:ss"`
7. **上传 OSS**：导航页修改后必须上传（总导航页上传根路径 `index.html`，迭代导航页按双路径大小写规则上传）。上传用 `oss-upload` 技能；前缀按项目，**发布是共享资源操作**——改总导航前先与线上 diff 确认无他人改动、备份、只追加不重排，上传后回归其他项目 Tab。取不到凭据时先排查 `credentialsFrom` 指向的既有脚本，确实拿不到才降级为本地预览并注明「未上传 OSS，交付未完成」。

## Step 6：Grep 验证

### 6.1 验证无遗漏

对**旧关键词**再次 Grep，确认所有活跃文档中已无残留：

```
Grep(old_keyword, glob="*.md", path="project_root")
Grep(old_keyword, glob="*.html", path="project_root")
```

**预期结果**：
- 活跃文档中匹配数 = **0**
- 历史快照中允许有残留（不改）

### 6.2 输出同步报告

```
## 同步报告

### 已修改文件
| 文件 | 修改处数 |
|------|:-------:|
| xxx  | N处     |

### Grep 验证
| 关键词 | 活跃文档匹配数 |
|--------|:------------:|
| xxx    | 0 ✅         |

### 未修改文件（历史快照）
- reviews/xxx.md — 评审快照
- prd/v1.md — 旧版本
```

## 常见变更场景速查

### 场景 A：重命名（如"渠道支出"→"渠道费用"）

```
关键词：旧名称
影响面：PRD主文档、功能列表、上下文文档、附录、所有HTML侧边栏
```

### 场景 B：删除字段（如删除"接入方式"）

```
关键词：字段名（中文+英文）
影响面：PRD字段表、校验规则、功能描述、原型表头/表单/JS逻辑
```

### 场景 C：新增字段/功能（如新增律师信息字段）

```
关键词：新字段名 + 关联模块名
影响面：PRD字段表、功能列表、原型页面、页面结构
```

### 场景 D：流程变更（如分成方式新增"固定费用"）

```
关键词：流程名 + 涉及的枚举值
影响面：PRD流程描述、字段表枚举值、校验规则、功能列表、联动规则
```

---

## 注意事项

1. **历史快照绝不修改**：评审文档、旧版本 PRD 代表特定时间点的结论，修改会失去追溯价值
2. **先改主文件再同步**：确保主文件是最终版本，避免同步时引入错误
3. **Grep 搜索要全面**：中文关键词 + 英文关键词 + 驼峰命名，都要搜
4. **nth-child 索引**：删除表格列后，HTML 中 JS 的 `nth-child()` 索引需同步调整
5. **侧边栏一致性**：所有同端页面侧边栏必须统一，改一个要改全部
6. **导航页同步不可遗漏**：每次修改后必须同步总导航页和迭代导航页（见 Step 5），包括页面数、PRD 版本徽章、卡片文案、卡片编号、最近更新时间（具体到秒），并上传 OSS
