# 工期预估 Skill

## 触发条件

用户要求对PRD/功能列表/迭代需求进行工期预估、人力评估、排期计划时自动触发。

## 输入要求

预估前必须读取以下文件（按优先级）：

1. **功能列表**：`prd/phase1-feature-list.md` — 获取功能编号、优先级、用户故事
2. **PRD主文档**：`prd/PRD-*.md` — 获取功能范围、已有功能说明、业务流程与业务逻辑（功能清单、改动面、状态流转）
3. **上下文**：`context.md` — 获取涉及端、迭代范围

## 预估方法论

### 第一步：识别角色与工作量驱动因素

| 角色 | 工作量驱动因素 |
|:----:|--------------|
| 产品经理 | 评审轮次（通常1~2轮）+ 验收标准 + UAT |
| UED设计师 | 新增页面数 × 端数 + 设计走查 |
| 后端开发 | 新增接口数 + DB变更复杂度 + 第三方对接 |
| 前端开发 | 新增/改造页面数 × 端数 + 交互复杂度 |
| QA测试 | 功能点数 × 场景系数 + 回归范围 |

### 第二步：后端工作量基准

按接口复杂度分级估算：

| 复杂度 | 基准人天 | 典型场景 |
|:------:|:-------:|---------|
| 高 | 1~1.5 | 支付对接、事务性操作、批量状态流转、原子性保证 |
| 中 | 0.5~1 | 标准CRUD含业务校验、分页查询含多表关联 |
| 低 | 0.25~0.5 | 简单状态过滤、单表查询、字段新增 |

额外项：
- DB变更（建表/加字段/状态扩展）：0.5~1人天
- 联调自测：占开发量的 20%~25%

### 第三步：前端工作量基准

按页面复杂度分级估算：

| 复杂度 | 基准人天 | 典型场景 |
|:------:|:-------:|---------|
| 高 | 1~1.5 | 多状态交互页（购物车列表含勾选/全选/汇总/批量操作） |
| 中 | 0.5~1 | 表单页（含校验）、详情页、浮层/弹窗 |
| 低 | 0.25~0.5 | 纯展示页、按钮改造、简单组件 |

注意：
- 每个端独立计算（Web + H5），不可简单合并
- H5端通常比Web端多 0.5~1 人天（移动端适配 + 跨端验证）
- 全局组件（如悬浮按钮）需单独估算
- 联调自测：占开发量的 15%~20%

### 第四步：UED工作量基准

| 页面类型 | 基准人天 |
|---------|:-------:|
| 新增复杂页面（列表/表单/支付流程） | 0.5 |
| 简单页面改造（按钮/浮层/弹窗） | 0.25~0.5 |
| 标注交付 + 设计走查 | 0.5 |

### 第五步：QA工作量基准

| 测试类型 | 基准人天 |
|---------|:-------:|
| 测试用例编写 | P0功能数 × 0.08~0.1 |
| 功能测试 | P0功能数 × 0.06~0.08 |
| 跨端测试 | 0.5~1 |
| 回归测试 | 涉及模块数 × 0.3~0.5 |
| Bug验证 + UAT配合 | 1~1.5 |

### 第六步：产品经理工作量基准

| 工作项 | 基准人天 |
|--------|:-------:|
| 评审整合（每轮） | 0.5~1 |
| 交互设计确认 + 原型验收 | 0.5 |
| 验收标准 + 验收用例 | 0.5~1 |
| UAT验收 + 问题跟踪 | 0.5 |

## 输出格式

### 文本输出（必须包含）

1. **角色汇总表**：每个角色的人天 + 占比
2. **各角色明细**：工作项 + 复杂度 + 人天
3. **周期估算**：考虑并行后的自然日周期
4. **风险项**：高复杂度工作项 + 影响 + 应对

### Excel输出（用户要求时生成）

使用 `scripts/generate_estimate.py`（Python + openpyxl）生成 Excel 文件，不再依赖 Node/`xlsx` npm 包。

**运行时**（本机绝对路径，已装 openpyxl，无需联网安装任何依赖）：
`$HOME/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3`，下文以 `$PY` 代指。

**生成命令**（可直接复制执行）：
```bash
PY=$HOME/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3
SKILL=$REPO/skills/effort-estimate
"$PY" "$SKILL/scripts/generate_estimate.py" \
  --name "迭代名称" \
  --data "数据JSON路径" \
  --output "输出路径.xlsx"
```

**命令行参数**：

| 参数 | 说明 | 缺省行为 |
|------|------|---------|
| `--name` | 迭代/项目名称 | `项目工期预估`；若 `--data` 中已有 `projectInfo.name`，以 JSON 为准 |
| `--data` | 数据 JSON 路径 | 缺省时使用脚本内置示例数据；路径不存在或 JSON 非法会直接报错退出 |
| `--output` | 输出 .xlsx 路径 | 技能根目录下的 `工期预估.xlsx` |
| `--print-template` | 打印数据 JSON 模板（DATA_TEMPLATE）后退出，不生成 Excel | — |

**查看数据 JSON 模板**（`--data` 需要提供的结构，含 `projectInfo` / `roles[].items[].task|complexity|days` / `risks` / `cycleEstimate`）：
```bash
PY=$HOME/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3
"$PY" "$REPO/skills/effort-estimate/scripts/generate_estimate.py" --print-template
```

如脚本不存在，参照模板新建，包含以下 Sheet：

| Sheet名 | 内容 |
|---------|------|
| 总览 | 项目信息 + 角色人天汇总 + 周期估算 |
| 产品经理 | 工作项 + 人天 |
| UED设计师 | 工作项 + 人天 |
| 后端开发 | 工作项 + 复杂度 + 人天 |
| 前端-Web | 工作项 + 复杂度 + 人天 |
| 前端-H5 | 工作项 + 复杂度 + 人天 |
| QA测试 | 工作项 + 人天 |
| 风险项 | 风险项 + 等级 + 影响 + 应对 |

Excel 由 Python 的 openpyxl 生成，运行时需使用上方标注的 Python 解释器，不要再安装 `xlsx` 等 npm 依赖。

## 注意事项

1. **不要低估联调**：前后端联调通常占总开发量 15%~25%，不可省略
2. **支付类功能加倍**：涉及支付对接、回调、原子性的功能，复杂度一律标高
3. **跨端不可简单合并**：Web 和 H5 是独立工作量，除非确认同一组人开发
4. **标注并行压缩**：给出「并行」和「串行」两种周期估算
5. **风险项必须列出**：复杂度为「高」的工作项自动归入风险项
